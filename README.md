# lucas-skills

Private Claude plugin with my personal skills.

```
.claude-plugin/plugin.json        plugin manifest
.claude-plugin/marketplace.json   marketplace (this repo = one plugin)
skills/<skill-name>/SKILL.md      the skills
agents/<agent-name>.md            subagents on cheaper models
hooks/hooks.json                  plugin hooks
```

## Install

claude.ai admin settings → Skills → Add → Sync from GitHub → pick this repo.

## Add or remove a skill

1. Create or delete `skills/<skill-name>/SKILL.md` (the folder name must match `name:` in the frontmatter).
2. Check it: `python3 .github/scripts/gen_marketplace.py --check`
3. Commit and push, then re-sync.

## Reporting rule

A `SessionStart` hook in the same file loads `hooks/reporting-rule.md` into every session, so Claude reports finished files, artifacts and plans in a few lines instead of restating them. Edit that file to change the rule.

It also loads `hooks/general-rules.md`: no "generated by" attribution, English Conventional Commits, and running only the tests related to the change. Edit that file to change the rules.

## Planning

`/planning` turns a task, ticket or bug into `plan.md`, an implementation plan for agents to execute. The plan is organized by order of work: each step has its own files, change, risks and proof. The order comes from `AGENTS.md`/`CLAUDE.md` when they set one, otherwise from a default (data → contracts → backend → client → UI → wiring). It saves to `docs/changes/<YYYY-MM-DD>-<slug>/plan.md` and leaves it uncommitted.

## Pull requests

- `/pr` writes a PR body (from [mattpocock/skills](https://github.com/mattpocock/skills)).
- `/pr-code-review` reviews a PR with terse one-line inline comments. The `claude.yml` workflow in `lucas-segundo/ai` uses it for reviews.
- `/pr-fix` follows up a PR's review comments: fixes, replies to and resolves your own, reports the rest.

## Design

`/designing-screens` designs screens and flows as interactive Artifact prototypes, or critiques existing ones.

## Subagents

`agents/` holds subagents that run simple tasks on cheaper, faster models, so the main model gets back short results instead of raw output.

- Haiku: `test-runner` (only the failures), `log-summarizer` (only the root-cause lines), `git-scout` (history questions), `doc-fetcher` (doc lookups, with sources), `bulk-editor` (exact edits across many files)
- Sonnet: `test-writer` (tests in the repo's own style), `fixer` (fixes for errors that are already diagnosed)

Each one is a Markdown file with `name`, `description`, `model` and `tools` in its frontmatter. The `description` tells Claude when to delegate.

A `SessionStart` hook loads `hooks/delegation-rule.md`, which maps each kind of task to its agent and tells Claude to delegate instead of working inline. Without it, the default system prompt tells Claude not to spawn agents unless asked. Edit that file to change the mapping.
